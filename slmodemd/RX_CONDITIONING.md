# Experimental signed-linear receive conditioning

This optional module provides a reproducible way to test the RX noise and
self-echo proposal in [D-Modem issue #13](https://github.com/strozfriedberg/D-Modem/issues/13#issuecomment-5619094216).
It operates on 16-bit linear PCM at the DSP sample rate. The optional `socket`
mode conditions received samples before the host's skip/processing decisions;
the default `processed` mode retains the earlier processed-sample pilot. Both
observe local TX through const pointers and never change its generated bytes,
insert output samples, or add noise to G.711 codewords. Altered RX can naturally
change what the modem chooses to transmit on later DSP iterations.

The proposed mechanism remains a hypothesis to test on each path. Component
checks establish the intended sample operations; they do not establish faster
negotiation, V.90 operation, better throughput, or an improved dropped-call rate.
This module neither changes the vendor carrier-loss threshold nor disables its
echo canceller.

## Build without changing the input tree

On Linux, install the normal D-Modem 32-bit compiler/development dependencies,
GNU make and binutils, Python 3.9 or newer, and GNU coreutils. From the repository
root:

```sh
python3 slmodemd/apply_rx_conditioning.py slmodemd
```

This builds `slmodemd-rxcond/slmodemd` using the source tree's own Makefile plus
libm. The optional second argument chooses another output directory. The source
directory and `dsplibs.o` are unchanged; no vendor instructions or private DSP
object offsets are involved. A temporary output is compiled and checked before
it becomes the requested output directory. Any existing destination is refused,
including an earlier successful build; choose a fresh directory to rebuild.

`rx-conditioning-build.json` records the conditioning API version and the source,
copied header, output binary, and unchanged vendor-object SHA-256 values. This is a build record, not call
acceptance. No modem process or SIP call is started by the installer or tests.

Run the resulting binary with the same command-line arguments as the original.
For example, a **socket-mode experimental control** uses the same causal read
constraint as the socket echo arm:

```sh
DMODEM_RXCOND=1 DMODEM_RX_ECHO_MODE=socket DMODEM_RX_SOCKET_CAUSAL=1 \
  DMODEM_RX_NOISE_DBFS= DMODEM_RX_ECHO_DB= DMODEM_RX_GAIN_DB=0 \
  ./slmodemd-rxcond/slmodemd -d2 -e ./d-modem /dev/slamr0
```

A **combined noise/echo arm** uses that same binary and bounded processing blocks:

```sh
DMODEM_RXCOND=1 DMODEM_RX_ECHO_MODE=socket DMODEM_RX_SOCKET_CAUSAL=1 \
  DMODEM_RX_NOISE_DBFS=-65 DMODEM_RX_ECHO_DB=-40 \
  DMODEM_RX_ECHO_SAMPLES=192 DMODEM_RX_GAIN_DB=0 \
  ./slmodemd-rxcond/slmodemd -d2 -e ./d-modem /dev/slamr0
```

Without `DMODEM_RXCOND=1`, the original socket reads, writes, and sample buffers
are retained. Other conditioning variables are ignored. Setting `DMODEM_RXCOND=1`
alone selects the earlier processed-mode control, with zero noise, zero echo,
and unity RX gain. Explicitly use `DMODEM_RX_ECHO_MODE=processed` to reproduce
that pilot. Keep the exact old binary when reproducing a recorded result.
For socket echo comparisons, set `DMODEM_RX_SOCKET_CAUSAL=1` on the control,
noise-only, echo-only, and combined arms. A separate noise-only socket comparison
can set it to `0` on both noise and control; it then needs no TX lookahead.

## Controls

| Environment variable | Default | Meaning |
| --- | --- | --- |
| `DMODEM_RXCOND` | `0` | `1` enables the experimental host path; only 0 or 1 is accepted. |
| `DMODEM_RX_ECHO_MODE` | `processed` | `processed` retains the earlier pilot; `socket` uses raw socket sample indices and correct sample skipping. |
| `DMODEM_RX_SOCKET_CAUSAL` | `1` when echo is configured; otherwise `0` | Apply the socket echo read constraint even to a zero-echo control. Socket echo rejects an explicit `0`. |
| `DMODEM_RX_NOISE_DBFS` | Omitted: no noise | Uniform pseudorandom noise RMS relative to 32768. Range -120 to -20 dBFS. |
| `DMODEM_RX_ECHO_DB` | Omitted: no echo | Amplitude gain of delayed local TX added to RX. Range -120 to -10 dB; -40 means multiplication by 0.01. |
| `DMODEM_RX_ECHO_SAMPLES` | DSP rate / 50 | Reference-index separation in the selected mode, from 1 through 4096. At 9600 samples/s, 192 indices span 20 ms of sample count; this is not a measured physical delay. |
| `DMODEM_RX_GAIN_DB` | `0` | Gain applied to original RX before adding echo/noise. Range -24 to 0 dB. |

Invalid enabled settings reject socket startup. Omitted noise or echo means
exactly zero addition; explicitly setting -120 dB is a small nonzero addition.
The generated noise uses a fixed per-call seed for reproducibility. At -65 dBFS,
its requested RMS is approximately 18.4266 signed-PCM units; uniform peak
amplitude is approximately 31.9162. Summation saturates at the int16 limits before
rounding. The shutdown summary reports clipped samples so saturation cannot be
mistaken for a benign intervention.

Read blocks are bounded by the smaller of 20 ms and the configured echo delay.
Socket causal mode further limits each read to the TX history actually available.
Reads preserve an odd trailing stream byte until its partner arrives. EOF halfway
through a PCM sample is an error. Socket mode retries interrupted/partial writes
using only the unsent byte suffix, preserving all generated bytes in order.
Processed mode retains the pilot's one-write policy. Call startup resets counters,
history, and any pending byte. Shutdown reports RX, TX, processed, skipped,
clipped, host-adjustment, and model-failure counts.

## Two sample clocks, neither a physical delay calibration

In `processed` mode, RX processed sample k receives a scaled copy of processed TX
sample k-192. Startup silence, delay padding, and completely discarded RX blocks
are outside that clock. The earlier host partial-skip behavior is retained in
this mode so the pilot remains separately reproducible.

In `socket` mode, raw RX sample k receives the scaled raw TX sample k-192. RX and
TX indices reset independently at socket startup. The original 192 startup TX
silence samples count as TX indices 0 through 191. Every successfully written TX
sample counts, including later host-requested padding. Every complete received
sample counts and is conditioned, including samples the host subsequently skips.
Before index 192 there is no local TX reference and no echo is added.

The host source computes a negative-delay input pointer using byte arithmetic,
then passes the original buffer to `modem_process` anyway. Socket mode fixes this
opt-in path using an `int16_t` offset: after an 80-sample skip the retained suffix
begins at sample 80, not byte 80 or sample zero. Complete dropped blocks still
advance the raw clock. Positive padding uses the unchanged host TX policy and is
recorded through the same successful-write path as generated TX.

Neither mode proves that the converter, packet path, bridge playout queue, or
telephone line has a physical 20 ms delay. Socket index alignment describes this
source boundary; the downstream transport can buffer, resample, or schedule
playout independently. These indices do not establish an acoustic echo path.

The host driver's `MDMCTL_IODELAY` value is a separate input to the vendor DSP.
This module does not change it. In stock D-Modem, the socket driver still reports
zero. Thus the combined example above does not implement every part of the issue
comment's suggested configuration. Selecting a host I/O delay requires a separate
measured experiment.

## Causal underflow makes an experiment unverified

Input skipping can consume the available delayed TX history. Socket causal mode
reduces reads when possible: for example, only 112 samples may remain available
after a partial skip. If no causal progress is possible, or an old reference has
been overwritten, the module reports `rxcond: MODEL FAILURE`, increments
`model_failures`, and returns `EPROTO`. It neither invents missing silence nor
adds TX to keep the model running. A zero-echo causal control uses the same checks.

Any such call is an **instrument/model failure**, including when the transport
then closes or the modem drops carrier. Preserve its observed modem outcome, but
exclude it from claims that conditioning made the modem better or worse. Missing
or incomplete model diagnostics also leave that conclusion unverified. A
noise-only socket arm with causal mode disabled can independently test the raw
receive/noise/skip path without this feedback constraint.

## Component and build checks

From the repository root:

```sh
cc -O2 -Wall -Wextra slmodemd/tests/rx-conditioning-test.c -lm -o /tmp/rxcond-test
/tmp/rxcond-test
# Linux with the normal 32-bit D-Modem build dependencies:
python3 slmodemd/tests/test_rx_conditioning_build.py
```

The C check covers inactive bypass, both clocks, noise mean/RMS and lag-one
correlation, odd-byte reads and partial-sample EOF, sample-exact echo, startup and
positive padding, complete and partial skips, smaller causal reads, exhausted or
overwritten history, partial/interrupted byte-exact writes, immutable TX,
saturation, call-state reset, and invalid settings. The build checks cover a real
i386 link against the public source/blob, source preservation, manifest hashes,
existing/symlink/nested destinations, compiler failure cleanup, a concurrent
destination, and incompatible source anchors. They never start a modem.

In the component run accompanying this extraction, 1,920,000 generated samples
measured -64.995822 dBFS RMS, mean -0.011148 PCM units, and lag-one correlation
-0.000579 for the -65 dBFS setting. This quantifies the generator, not telephone
line noise or a connection improvement.

For hardware comparisons, alternate control, noise-only, echo-only, and combined
arms on the same binary. Keep settings and per-device results separate. Record
all attempts, setup failures, both final negotiated rates, payload integrity and
throughput, retrains, held duration, unexpected disconnects, and model failures.
Report attempted calls, established sessions, and unverified outcomes separately.
An announced CONNECT rate by itself is not end-to-end acceptance. Observing at
most 1% unexpected drops over 100 or more established calls does not establish a
95% population bound below 1%; even zero drops needs 299 independent calls for
that one-sided bound, and correlated line conditions limit the inference.
